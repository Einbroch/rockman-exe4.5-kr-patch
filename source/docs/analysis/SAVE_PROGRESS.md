# 록맨 저장 대사·영속 저장 검증 (2026-09-24)

후속 고정폭 표시 PoC는 `FIXEDCELL_PROGRESS.md`, 실제 도감 제목 번역을 추가한
2026-09-25 최신 누적 개발본은 `LIBRARY_PROGRESS.md`에 있다. 아래 내용은 보존한
save-v1 ROM의 검증이며 다른 ROM에 자동으로 적용하지 않는다.

## 이 단계의 개발본

- ROM: `poc/output/exe45_ko_development_save_v1.gba`
- SHA-256: `077eb3d017fef5c0b2ab39c49fb5d887f673a270ca91ac18a88296522cd84a35`
- 9,561,536바이트. `_repro.gba`, `_final_repro.gba`와 동일한 해시다.
- 누적 65개 번역 단위: 소개 4 + PET 45 + 저장 16. 검토 전 초안·배포 금지 개발본이다.
- 원본 ROM은 `project.json`의 해시를 유지한다. 미수정 아카이브 729개와 포인터 보존.
- 이전 PET 선택 빌드 회귀 출력도 기존 `c2c64a0d...`와 동일하다.

EXE3 분석의 원본 고정·왕복 검증·수정 범위 제한 원칙을 계속 적용했다. 이전 단계의
검증은 해당 ROM 해시에 대한 역사적 자료이며 새 ROM의 실행 검증으로 자동 이전하지 않는다.

## 이번 변경

`translations/megaman_save_ko.json`은 `6DA21C`의 록맨 저장 분기 script 0~4만
선택한다. 저장 확인, 덮어쓰기 경고, 쓰기 중 전원 경고, 성공, 실패/재시도,
비정상 데이터 경고의 16개 리터럴을 9개 명시적 문구에 연결했다.

원본 9,008바이트에서 9,303바이트로 증가한 아카이브는 `0x8007A0`에 재배치한다.
카탈로그 포인터 `0x3BC7C`, `0x3BF6C`를 함께 갱신한다. 두 포인터의 기대 원본값,
신규 대상, 전체 ROM 수정 차분과 헤더 보존은 제품 빌드가 검사한다.
일반 대사 폰트 위치는 입력 크기에 따라 `0x802BF8`로 이동하며 훅·리터럴도 파생한다.

이 아카이브는 록맨 외 다른 내비게이터와 고정폭 표시 스크립트를 공유한다.
`archive_scripts.py`는 채택한 120개·16비트 상대 오프셋·단조 경계 구조에서
선택하지 않은 115개 스크립트의 바이트와 빈 항목을 전부 비교한다. 역순/지원하지
않는 공유 경계는 거부한다. 이 검사를 일반적인 임의 아카이브 경계 발견기로 쓰지 않는다.

빌더는 부분 번역 범위를 `literal_scripts`로 명시하게 하고 해당 스크립트 안의
전체 리터럴을 요구한다. 나머지 원문·제어 구조는 유지한다. 다른 내비게이터의
대사나 `mmbn45s` 라벨을 한글로 해석하거나 대사 폭 제한으로 재단하지 않는다.

저장 대사 최장 줄은 121픽셀, 선택지 행은 104픽셀이다. 채택한 대사 표시 범위
144픽셀 이내다. 실패 후 재시도 선택지는 원본처럼 두 번째 행에 남도록 검사한다.
`callSave`, 결과 분기, 플래그, 대기 시간과 페이지 제어는 바꾸지 않았다.

## 실행 검증

정본 보고서: `analysis/exe45_save_ko_runtime.json`.
직접 검토한 35장과 10개 결과 파일은 `analysis/save_runtime_observations_v1.json`의
고정 해시로 연결한다. 저장 문구에서 관찰된 한글 35종의 폰트 레코드 읽기도 확인한다.

| 확인 범위 | 결과 |
|---|---|
| 새 빌드 첫 소개·다음 페이지 | 3줄 표시, A 진행, 한글 지우기 |
| PET 7개 메뉴 | 확인문/선택지 표시, 아니요 뒤 대기문 복귀 |
| 저장 화면 | 한글 확인문·예/아니요, 위쪽 원본 통계 필드 유지 |
| 저장 중 | 전원을 끄지 말라는 한글 경고 두 줄 |
| 저장 완료 | 완료 메시지 후 A로 PET 복귀 |
| 덮어쓰기 아니요 | PET 복귀, `.sav` SHA-256 전후 동일 |
| 덮어쓰기 예 | 한 실행에서 쓰기 완료, `.sav` 내용 변경, PET 복귀 |
| 디스크 기반 다시 시작 | 체크포인트 없이 새 프로세스에서 부팅→이어하기→록맨 선택→PET |

저장 문구 9종 중 6종을 실행으로 관찰했다. `save.failed`, `save.retry`,
`save.invalid`는 원문·제어코드·폭·바이너리 검증만 통과했으며 오류를 강제하지 않았다.

첫 저장은 짧은 캡처 구간이 쓰기 중에 끝나 진단 체크포인트에서 이어 완료했다.
이것을 중단 없는 첫 저장이라고 주장하지 않는다. 이후 덮어쓰기는 600프레임 대기
구간을 둔 한 실행에서 완료했고, 그 파일을 사용한 콜드 부팅도 한 실행에서 수행했다.
최종 검증 저장 파일 SHA-256은
`de890e26c3709275c83cd66efaabe65cca9ece7e347394b6e609cff0398c100c`다.

## 테스트 환경 및 보존 경계

별도 에뮬레이터: `poc/runtime/isolated-mesen-save-v1/Mesen.exe`.
별도 저장 폴더: `poc/runtime/save-v1-persistence`.
원래 에뮬레이터의 기존 세이브를 새 저장 검증에 사용하거나 덮어쓰지 않았다.
격리 검증 전후 기존 `.sav`/`.rtc` 목록의 해시가 같은 것을 확인했다.

`capture_save_qa.py`는 에뮬레이터와 저장 폴더가 프로젝트의 `poc/runtime` 안에
있는지, 복사본 설정의 저장 경로가 명시한 폴더인지, ROM/실행기/BIOS 해시가
일치하는지 검사한다. 실행 전후 저장 파일 해시와 실행 뒤 파일 스냅샷을 남긴다.
RAM·스크립트·진행 플래그·저장 파일 내용은 직접 수정하지 않는다.

사용 에뮬레이터의 CLI는 문자열 폴더 경로를 설정하는 데 적합하지 않아 격리한
portable 복사본의 설정만 수정했다. 근거는 사용 빌드의
[ConfigManager 소스](https://raw.githubusercontent.com/nesdev-org/MesenCE/20ba206cef5ba207c21203176d02cb9f43dda9fb/UI/Config/ConfigManager.cs)다.
외부 실행 환경·BIOS는 로컬 검증 자료이며 배포물에 포함하지 않는다.

실패한 환경 구성도 보존했다. `save-v1-cold`는 BIOS 누락으로 검은 화면이었으나
실행기는 완료 플래그를 남겼다. 이는 게임 검증 실패다. 다음 복사 시도에서
`Firmware/Firmware`로 중첩된 것을 발견해 해당 테스트 프로세스만 중지했고,
정확한 경로의 BIOS 해시를 확인한 후 `save-v1-cold-verified-bios`를 새로 실행했다.
제품 ROM의 바이트는 이 과정에서 바꾸지 않았다.

## 재현과 남은 작업

```powershell
python -X utf8 -m unittest tools/test_text_catalog.py tools/test_korean_codec.py tools/test_tpl_literals.py tools/test_development_font.py tools/test_archive_scripts.py
python -X utf8 tools/build_development_patch.py --work poc/visibility/work-save-next --out poc/output/exe45_ko_save_next.gba
python -X utf8 tools/report_save_runtime.py --out analysis/exe45_save_runtime_recheck.json
```

단위 테스트 22개 통과. 보고서 재검사는 보존된 증거를 확인하는 것이지 에뮬레이터를
다시 실행하는 것은 아니다. 이미 존재하는 출력은 새 이름을 사용한다.

격리 환경과 같은 ROM의 콜드 부팅 경로를 확보한 후 `capture_save_qa.py --mode enter`
및 `--mode commit`으로 진입·첫 저장을 재현할 수 있다. 커스텀 입력은 해당
`result.json`과 `save_environment.json`에 있다. 현재 세이브를 보존하려면 새 별도
환경/저장 폴더를 사용한다. 저장 전 체크포인트를 불러와 최신 세이브에 쓰면 안 된다.
