후속 최대 부하·아이콘 시험은 `CHIP_LIBRARY_TIMING_PROGRESS.md`와

통과했으나 첫 진입 갱신의 1프레임 추가 지연을 발견해 성능 문제는 열려 있다.
번역과 ROM은 아래 72단위 그대로다.

`poc/output/exe45_ko_development_chip_library_v1.gba`가 최신 선택형 개발본이다.

`ce839b60c8125da7ca8ce0240bcdfc82a8e8f5604202449af1acffa80158cbff`.
원본과 이전 69단위 ROM은 보존했다. 소개 4 + PET 45 + 저장 16 + 도감 제목 4 +
칩 이름 3 = **72개 번역 단위**이며 전체 게임의 번역률은 아니다.
새 명칭은 `캐논`, `에어슛`, `발칸1`; 도감의 실제 관찰된 세 항목에 한정한

체크포인트는 같은 ROM의 계보가 검증된 것만 사용했고 RAM·진행도 주입은 없다.

총 97개 캡처를 해시 검증했다. 칩 선택기의 **52,808회 반환 ABI/행·패딩 검사**와
**21,834회 실제 BIOS 글리프 복사 검사**를 통과했다. 별도로 표준 도감 8개 화면에서
선택된 한글·숫자의 잉크/그림자 픽셀 마스크, 7행 전체 타일 및 후행 0을 대조했다.
도감 제목 10개 화면과 2회 압축 해제의 전체 EWRAM 변경 경계도 재검사했다.

이름 입력 화면의 VRAM `8000..8FFF`는 원본 그래픽 `63ABF4..63BBF3`와 일치했고,
이후 도감 재진입에서 한글이 다시 공급됐다. 원본 저장 파일 2개는 이전 해시 그대로다.
새 테스트 저장 파일은 65,536바이트, SHA-256
`99bb577ddf75253833ad57b711a9eb59930c35c7837e6ae8597cb570bdbdb470`이며
저장 완료→새 실행 전→새 실행 후 값이 같고 마지막 PET 화면까지 확인했다.

정적/합성 검사와 실제 실행은 구분한다. `exe45_chip_library_cpu_v1.json`의
**11,710개 합성 CPU 벡터**는 11,172개 한글 번호, 7행·팔레트·8셀 경계,
사설 풀 256개·원본 둘째 풀 137개·폴백 5조건을 포함한다. 이는 Unicorn TI925T
모델과 대체 CpuSet을 쓴 검사이며 GBA 실기·최악 부하 타이밍 근거가 아니다.
제품 빌드는 이 검사 엔진을 의존하지 않는다. 기존 30개+칩 확장 5개 단위 테스트와
화면 보고서의 정상/잘못된 행 배치/잘못된 글꼴 거부 3개 검사를 합쳐 38개를 통과했다.

## 검사 중 구분한 사항과 남은 완료 조건

- 첫 `chip-ko-v1-cold`는 잘못 지정한 가드 바이트로 실행 전 차단됐다. 수정된
  `cold-guarded`만 성공 근거다. 실패 디렉터리는 보존했다.
- 보고서 초안은 프레임 끝의 EWRAM 행 버퍼를 영구 사본으로 가정해 실패했다.
  그 시점의 앞쪽 임시 버퍼 내용이 달랐다. 정확한 후속 쓰기 주체는 아직 확정하지 않는다. 파서 반환 시점에
  읽기 전용으로 기록한 바이트와 현재 BG 맵을 비교하도록 수정했다. ROM 수정은 없었다.
- 도감 진입 전후의 첫 64바이트도 불변이 아니다. 원본 장면 초기화가 바꾸므로
  경계 스냅샷 검사는 **진입 완료 이후** 화면끼리 비교한다. 캐시 범위 밖에 새 복사가
  없는지는 복사 호출의 목적지 범위 검사가 별도로 담당한다. 모든 순간의 쓰기 추적이나
  전역 VRAM 독점권을 이 결과로 주장하지 않는다.
- 아직 중요한 미완료 조건은 **실제 게임에서 최대 56개 한글 셀의 동시 갱신 부하**, 
  조건부 아이콘 표시와의 공존, 내용이 있는 P.A 및 별도 5행 경로, 다른 종료 경로다.
  실제 실행에서 한글 11,172개를 모두 표시했다는 뜻도 아니다. 음성/오디오는 비활성화했다.
- 다른 소비자·칩 설명·다른 메뉴와 전체 게임 번역, 문구·미감 검토는 남았다.
  후속 격리 시험에서 최대 부하·아이콘 공존을 확인했으나 초기 갱신 간격 문제가 생겼다.
  다음은 글리프/아이콘 부하의 인과 분리와 갱신 설계 검토다. 상세는
  `CHIP_LIBRARY_TIMING_PROGRESS.md`를 따른다. 3개 이름의 성공을 다른 경로의 완료로 넘기지 않는다.

## 이름 데이터와 소비자

| 원본 이름 풀 | 스크립트 | 비어 있지 않은 항목 | 서로 다른 비어 있지 않은 문자열 |
|---|---:|---:|---:|
| `0x765190`, 2,437바이트 | 256 | 249 | 249 |
| `0x765B18`, 1,103바이트 | 137 | 100 | 99 |

합계 393개는 **물리적 스크립트 분모**다. 게임에서 도달 가능한 칩 393종이라는 뜻이
아니다. 두 풀 모두 최대 8개 셀, 사용된 문자 코드 최댓값 `0x82`이며,
본문은 단일 바이트 문자와 `E5` 종료로 이루어진다. 오프셋 표까지 바이트 동일 왕복했다.
두 풀을 가리키는 카탈로그상의 포인터는 각각 9개이며, 원본과 개발본 모두 검증했다.
따라서 모든 포인터를 한글 풀로 옮기는 방식은 미구현 소비자를 함께 바꾼다.

원본 칩 이름 파서는 `0x08042FB0..0x08042FE4`다.

- `r0`: 선택된 이름 스트림, `r2/r3`: 상·하단 타일맵, `r6`: 팔레트/기저.
- 문자 `< E5`: 위 타일 `r6 + code*2`, 아래 타일은 그 값 +1.
- 종료 이후 8셀까지 타일 값 **0**으로 채운다. 팔레트가 붙은 공백으로 바꾸지 않는다.
- `E4` 이중 바이트 및 `F9 FC` 한글을 지원하지 않는다. 제목용 처리기와 별개다.
- 실제 관찰된 도감 버퍼: `0201E600`, 행 간격 32바이트, 7행.
  각 행은 상단 16바이트와 하단 16바이트다.
- 실제 반환 주소는 `08042EE5`; 상·하 버퍼 각각 +16, 스트림은 종료 문자에 남는다.

상위 선택기 `08042E50`은 r5 상위 니블로 행 수를 받아 처리한다.
별도 `08042F14` 선택기는 5행으로 같은 원본 파서를 호출한다. 이번 정상 진행에서는
5행 호출을 실행하지 못했다. P.A 목록도 테스트 세이브에서 비어 있었다.
두 경로를 같은 실행 검증으로 합치지 않는다.

현재 도감에서 실제 문자열 주소를 확인한 항목은 풀 `765190`의 스크립트
1(キャノン), 4(エアシュート), 15(バルカン1)이다.
화면상 도감 번호 1/4/5와 스크립트 번호 1/4/15를 혼동하지 않는다.
`??`는 번역된 제목 해제본의 스크립트 4, RAM `0202405D`에서 읽힌다.
조사는 이 미등록 항목의 타일과 후행 0 채움도 검사한다.

## 적재 창과 상주 수명

초기화 로더 `08042778`의 자산 23개를 원본 표·해제 결과에서 산출했다.
이름용 원본 글꼴은 `08601738`에서 VRAM `06004000..060067FF`로 160셀을 적재한다.
그러나 **160은 적재량이지 번역 코퍼스의 고유 한글 수 상한이 아니다**.

조건부 아이콘 전송의 목적지도 별도로 확인했다. 함수 `08043014`는 행 데이터의
바이트 +3이 0이 아닐 때만 128바이트씩 최대 7개를 전송한다.

| 탭 | 원본 코드가 지정한 아이콘 범위(끝 제외) |
|---|---|
| 스탠더드 | `06006200..06006580` |
| 메가 | `06006600..06006980` |
| 기가 | `06006A00..06006D80` |

이번 세이브에서는 이 조건부 전송 자체가 관찰되지 않았다. 표는 정적 근거다.
다른 게임의 `06006580` 빈칸 가설을 그대로 사용하면 메가/기가 아이콘과 충돌할 수 있다.

새로 조사한 `06008000..06008FFF`는 전역 빈 VRAM이 아니다.

1. 도감 진입·스크롤·네 탭 왕복 1,131프레임에서 이 범위의 쓰기는 없었다.
   비교 대조인 BG 맵 쓰기는 2,295,808회 관찰됐다.
2. 하지만 초기화 프레임 203에서 BG0 맵의 1,002개 항목이 `06008000` 타일을 참조했다.
   빈 셀을 제외한 스냅샷만 검사하면 놓칠 수 있다. 첫 타일을 캐시로 쓰는 가설은 기각한다.
3. 도감 종료→PET 후속 대화→취미 이름 입력까지 1,937프레임을 별도로 관찰했다.
   입력 화면 진입 시 모든 128타일이 다시 쓰인다.
4. 원본 `0863ABF4`의 9,600바이트 그래픽이 프레임 1634에 전송 예약,
   1635에 복사되고 1636부터 해당 타일맵 참조가 시작된다.
   마지막 입력 화면의 `06008000..06008FFF`는 그 원본 바이트와 전부 일치했다.

가능성을 더 조사할 설계는 **도감에만 귀속되는 7행×8셀 동적 캐시**다.
전체 11,172자 ROM 글꼴 중 화면에 필요한 56셀(3,584바이트)만 공급하면
번역 어휘를 146종 등으로 제한할 필요가 없다. 첫 셀을 피한
`06008040..06008E3F`는 후보일 뿐 **아직 할당을 채택하지 않았다**.
이 구간도 과거 PET 그래픽의 비영(非零) 데이터를 가지고 있으므로,
0 패턴이나 한 장의 화면을 빈 공간 증거로 삼을 수 없다.

## 실행 근거와 실패 기록

- `poc/runtime/chip-library-survey-v4`: 18/18 캡처, 도감 초기화 전의 같은-ROM
  PET 체크포인트에서 정상 패드 입력. 이름 파서 10,556회,
  서로 다른 스트림/행/팔레트 조합 14개를 바이트 기대값과 비교했다.
- `poc/runtime/chip-library-lifetime-v1`: 16/16 캡처. 종료와 후속 대화, 이름 입력을
  관찰했다. 마지막은 이름 입력 화면이며 **재진입 성공 경로가 아니다**.
- 직접 확인한 v4 화면: 3(첫 도감), 8(발칸 그림/설명), 12(스크롤),
  13(메가), 14(기가), 15(P.A), 18(스탠더드 복귀).
- 직접 확인한 lifetime 화면: 10(PET 복귀 대화), 13(취미 질문), 16(이름 입력).
  이는 기술 관찰이며 사용자 미감/용어 승인이 아니다.
- 별도 `isolated-mesen-chip-survey`와 `chip-survey-saves` 사용.
  조사 중 `.sav` 해시는 유지됐고 RTC 시간만 진행했다. 이전 완성 테스트 세이브와 분리했다.
- v1은 에뮬레이터 의존 파일 누락으로 시작 실패. v2는 Lua 기록 함수의 이름 충돌로
  칩 관찰 파일이 생성되지 않았다. v3은 참조 목록의 32건 상한 때문에 전체 주소 분포를
  증명하지 못했다. 이들은 v4의 성공 근거에 포함하지 않는다.
- 기록 함수를 고유 이름으로 수정하고, 완료 시 관찰 파일·호출·전송·프레임 수가
  비어 있으면 실패하도록 했다. v4 이후에는 전체 타일별 참조 누계를 저장한다.

## 다음 구현의 선행 조건과 재현

원본 이름 풀과 9쌍의 공유 포인터를 보존하고, 도감의 7행 이름 선택 경로에만
별도 한글 이름 풀을 공급하는 방향이 유력하다. 원본 선택기 내부의 `08042ED8` 부근은
