> 이 문서는 소개 대사 단독 단계의 역사적 기록이다. 후속 PET 45개 단위 추가,
> 누적 개발본, 쉼표를 포함한 코덱 v3 및 최신 남은 작업은 `PET_MENU_PROGRESS.md`를 따른다.

- 65A578 아카이브는 143바이트에서 276바이트로 커져 ROM 확장 시작점으로 옮긴다.
- 다른 731개 아카이브와 그 포인터는 원본 그대로 보존한다.
- 제어코드·문자열 의미·바이너리 왕복, 허용 쓰기 범위, 헤더 보존을 매 빌드 검증한다.
- 빌드 2회 결과 SHA-256은
  `a1b3078664809acfd001b3e293cc5b24d3aa6d722dc9d8968af15a122c9811fa`로 같다.
- 첫 소개문은 콜드 부팅에서 정상 표시되고 A 입력 뒤 다음 일본어 대사로 진행한다.
- 재회 대사(script 2)는 재삽입·왕복 검증까지 통과했다. 실제 재회 경로 검증은 남았다.
- 현재 사용 파일은 `poc/output/exe45_ko_development.gba`다. v2 런타임 검증본과
  바이트 해시가 같다. 배포 패치가 아니라 로컬 실행용 개발 ROM이다.

번역문은 검토 전 초안이다. 전 게임 한글화·배포 가능·전체 UI 지원을 뜻하지 않는다.

## 역해석 충돌 원인과 수정

영문 패치 레퍼런스의 `mmbn45` 명령 DB는 `F9 0C` 계열에서 상위 비트를 느슨하게
매칭한다. 일반 `printString`뿐 아니라 이름·음식·형제 등 70개 전용 명령도 포함된다.
이 때문에 `F9 FC` 뒤의 음절 번호 일부가 명령 인수로 해석됐다.

`tools/textpet_korean.py`는 해시가 고정된 원본 플러그인을 작업 폴더로 복사한 뒤,
71개 명령의 두 번째 마스크 바이트를 `0F`에서 `1F`로 바꾼다. 선언된 인수가 사용하지
않는 비트 4를 0으로 요구하여, 비트 4가 1인 `FC`를 한글 문자표가 처리하게 한다.
기존 인수·게임 내 네이티브 명령 처리기·원본 외부 파일은 수정하지 않는다.

초기 v1 검사는 11,172자를 한 문자열로 이어 붙인 테스트만 통과했다. 실제 문장
첫 글자인 `오`, `너`에서 전용 명령과 추가 충돌이 발견되어 v1 결과는 충분한 근거가
아님을 확인했다. 현재 근거는 **v2** 보고서다.

`analysis/exe45_korean_codec_roundtrip_v2.json`의 분모:

- 연속 문자열 안의 한글 11,172자
- 각 스크립트 첫 글자 한글 11,172자
- `keyWait` 명령 직후 한글 11,172자
- 원본 732개 아카이브 전체의 추출→재삽입 페이로드 1,065,382바이트

모두 독립 인코딩 예상값·의미 재추출·바이너리 재컴파일을 통과했다. 이 결과는
카탈로그 밖 동적 문자열이나 다른 게임 내 렌더러 지원의 증거가 아니다.

## 재현 명령

프로젝트 폴더에서 실행한다. 작업·출력 경로가 이미 있으면 새 이름을 사용한다.
기존 산출물을 자동 삭제하거나 덮어쓰지 않는다.

```powershell
python tools/verify_korean_roundtrip.py --work poc/visibility/work-codec-check --report analysis/exe45_korean_codec_check.json
python tools/build_development_patch.py --translations translations/megaman_intro_ko.json --work poc/visibility/work-intro-build --out poc/output/exe45_ko_development.gba
python -m unittest tools/test_text_catalog.py tools/test_korean_codec.py tools/test_tpl_literals.py
```

첫 소개문 런타임 경로·입력·에뮬레이터·캡처 해시는
`analysis/exe45_intro_ko_runtime.json`을 따른다. 예전 두 글자 PoC 빌더는 역사적
실험이며, 새 번역 작업의 제품 빌드 경로로 사용하지 않는다.

## 소개 단계 당시의 다음 작업 경계

1. PET 메뉴 확인 대사(65A608)는 일반 대사 경로이지만 선택지, 동적 이름 삽입,
   빈 줄 및 `\n` escape를 포함한다. 리터럴 어댑터의 지원 범위를 늘리고 해당
   아카이브 원본 왕복을 먼저 검증한 뒤 번역한다. 현재 빌더는 이 범위를 거부한다.
2. 별도 메뉴·전투 글꼴은 원본 소비 주소를 먼저 추적한다. 대사가 표시된다는
   이유로 고정폭 이름·칩·목록도 한글화되었다고 판단하지 않는다.
3. 재회 분기, 메뉴 선택지, 페이지 지우기, 장시간 플레이, 저장/불러오기,
   하드웨어/별도 에뮬레이터 검증을 확장한다.
4. 완성 번역 초안의 전체 글리프 수요·화면 폭 검증과 사람의 문구 검토가 남았다.

## 라이브러리 고정폭 경로에서 추가 확인한 사실

`analysis/exe45_library_font_consumers.json`에 원본·빌드·에뮬레이터 실행 결과와
코드/실제 IWRAM 바이트 대조를 묶었다.

| 자산 후보 이름 | ROM 범위 | 관찰 |
|---|---|---|
| monofont | `0x619EF8..0x620EF8` | 480회 읽기, 64바이트 레코드 복사 경로 |
| bigfont | `0x601738..0x607F38` | 같은 복사 경로 576회, 별도 BIOS 주소의 일괄 읽기 5,120회 |

두 자산 모두 런타임 `0x0300689C`의 글리프 복사 루틴을 거친다. 원본 ROM의
`0x1EF79C`에 해당하며, 캡처한 IWRAM과 코드 바이트가 같다. 루틴은 글리프 번호를
6비트 왼쪽으로 이동해 호출자가 넘긴 `r6` 글꼴 주소에 더하고 32비트 값 16개를
복사한다. 이 경로는 일반 대사의 96바이트 레코드 렌더러와 다르다.

상위 스트림 루프 `0x03006824..0x03006890`는 `E4` 문자 확장과 `E5` 이상 명령을
처리한다. **여기에는 아직 한글 처리를 설치하지 않았다.** 모든 호출자, 셀의 실제
가로·세로 배치, 목적 버퍼→VRAM 관계, 메뉴별 텍스트 범위를 다음에 확정해야 한다.
화면의 모든 라벨이 어느 글꼴을 쓰는지는 이 읽기 집계만으로 확정하지 않는다.
