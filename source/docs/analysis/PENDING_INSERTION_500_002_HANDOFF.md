## 후속: 500개 실제 적용을 위한 명시적 페이지 배치

사용자가500개씩 실제 ROM에 반영하면서 작업하도록 재지시했다. 이후 묶음의 적용 완료 조건은 실제 주 빌드 누적 ROM 반영과 소비 경로 검사이며, 준비 검사나 CPU 시험만으로 적용 완료라고 표시하지 않는다.

세 미해결 문구의 말은 변경하지 않았다. `translations/pending_insertion_500_002_pages.json`에서41:1은3행으로 배치하고,49:1/55:2는 각각2페이지로 배치했다. 두 페이지 사이에 정확히 native keyWait(any=false)+clearMsg를1쌍씩 추가한다. 원래 페이지 종료 명령과 모든 임무/변수/보상/분기 명령은 그대로다. 사용자에게 보여주는 페이지 진행은 총2회 늘어나며 실제 실행/표시 검증은 아직 필요하다.

`tools/pending500_002_pages.py`는 원본 ID→생성된 리터럴 fragment ID 대응을 유지한다. 추가 두 리터럴로 후속 literal 번호가 이동하더라도 원본 선택500개 분모가502개로 늘어나지 않는다. 모든 fragment의 문자/폭을 검사하며, 원문과 번역 권위의 ID를 변경하지 않는다. 생성한 구간을 정확히 접어 원래 번역 TPL로 환원해 native 명령 전체와 문구/숫자/순서 보존을 검사한다.
