# 56셀/아이콘 조건부 시험

기준 ROM은 72단위 `ce839b60c8125da7ca8ce0240bcdfc82a8e8f5604202449af1acffa80158cbff`다.
기준 경로는 `chip-ko-v1-input-lifetime`의 같은-ROM PET 체크포인트에서
`none:1:60,a:2:90,a:2:120,none:1:120`으로 도감에 진입하는 경로다.

질문: 매번 다시 복사하는 56셀과 조건부 7개 아이콘이 동시에 실행될 때
실제 BIOS 복사·VRAM 글자/아이콘 보존·이름 처리 주기가 유지되는가?
우선 순수 읽기 전용 `chip-ko-v1-timing-native`에서 7글리프/7행과 아이콘 0회를
관찰했다. 정상 상태에는 최대 부하의 전제 조건이 없다.

격리 시험은 ROM 파일·RAM·저장 플래그를 쓰지 않고, 지정된 CPU 읽기의 반환값만
시험 입력으로 대체한다. 원본 코드 `42E84/42EC8`의 현재 7행 기술자 ID/분류 읽기는
이미 정상 경로가 확인된 칩 ID 1/분류 1로, `4302C/4303C`의 아이콘 유무/ID 읽기는
1로 대체한다. 아이콘 유무 바이트는 원본 초기화 `429BE`가 설정하는 조건이다.
진행도/획득 조건은 우회되므로 이 시험은 정상 획득·저장·분기 도달을 증명하지 않는다.

사설 스크립트 1을 읽는 새 렌더러 안에서만 8개 F9FC 글리프와 E5를 반환한다.
행/열별 번호는 0..54와 마지막 11171로 56셀 전체·마지막 한글을 덮는다.
실제 ROM 글꼴, 설치 코드, GBA BIOS, PPU, 원래 선택기/아이콘 함수는 그대로 실행한다.
이 방식은 Mesen의 읽기 콜백 반환값 대체 기능에 기반한다. 최신 공식 소스 참조:
https://github.com/SourMesen/Mesen2/blob/master/Core/Debugger/ScriptingContext.cpp
`InternalCallMemoryCallback`의 반환값 처리. 현재 사용 바이너리에서 별도로 효과를 검증한다.

통과: 모든 56셀 및 아이콘 복사 바이트, 타일/글리프 공급과 관찰된 갱신 주기 확인.
실패: 범위 침범·잘못된 픽셀 공급 또는 기준 대비 프레임 주기 저하 등 회귀.
미해결: 주입 지점·양성 대조 또는 관찰 수가 부족한 경우. 단순 부팅/스크린샷 성공은 통과가 아니다.
주기 저하가 나타나면 캐시 재사용/갱신 시점 변경을 조사하며 어휘를 줄이지 않는다.

별도 시험 결과의 체크포인트는 `diagnostic_checkpoint.mss`로 격리하여 정상 경로의
시작점으로 재사용하지 못하게 한다. 음소거 Mesen 결과이며 오디오·실기 지원 판정이 아니다.
생산 번역 입력이나 빌드 내용에 이 개입을 추가하지 않는다.
